# BioClinical-ModernBERT 讲解文档

## 1. 项目是做什么的

`BioClinical-ModernBERT` 是一个围绕论文 **BioClinical ModernBERT** 搭建的研究代码仓库，目标是把 `ModernBERT` 用在生物医学和临床文本场景中。

这个仓库主要提供两类能力：

1. 下游任务微调与评估。
2. 持续预训练所需的配置文件和数据转换脚本。

需要特别注意：

- 仓库 **不包含完整的 continued pretraining 训练代码**。
- 真正的继续预训练流程依赖上游 `ModernBERT` 仓库。
- 当前仓库更像是一个“实验复现与下游评测工程”。

## 2. 整体结构

项目核心目录可以这样理解：

```text
BioClinical-ModernBERT/
├── main.py                         # 下游任务训练与评估入口
├── multiprocess_bench.py          # 推理速度测试
├── src/
│   ├── dataloader/
│   │   └── dataloader.py          # 各数据集读取、清洗、切分、缓存
│   ├── tasks/
│   │   ├── sequence_classification.py
│   │   ├── token_classification.py
│   │   └── mask_classification.py # 不同任务的 Trainer 封装
│   └── metrics/
│       └── metrics.py             # 评估指标
├── pretraining_resources/
│   ├── convert_dataset_to_mds.py  # CSV -> MDS 转换
│   └── configs/                   # continued pretraining 配置
├── scripts/
│   └── run_parallel.sh            # 多 seed 并行运行脚本
├── results/
│   └── aggregate_results.py       # 聚合多次实验结果
├── data/
│   ├── raw/                       # 原始数据手动放这里
│   └── processed/                 # 预处理后的 HF Dataset 缓存
├── checkpoints/                   # 训练保存的最佳 checkpoint
└── outputs/                       # 每次实验导出的日志结果
```

## 3. 项目主线流程

如果只看下游任务，执行链路非常清晰：

1. 运行 `main.py`。
2. 根据 `--dataset` 调用 `get_data()`，加载对应的数据集包装类。
3. 数据集包装类负责：
   - 读取 `data/raw` 中的原始文件；
   - 清洗并转成 Hugging Face `Dataset` / `DatasetDict`；
   - 划分 `train / validation / test`；
   - 把结果缓存到 `data/processed`。
4. `main.py` 根据 `problem_type` 自动选择对应 Trainer：
   - `multi_label_classification` / `single_label_classification` -> `SequenceClassificationTrainer`
   - `token_classification` -> `TokenClassificationTrainer`
   - `mask...` -> `MaskClassificationTrainer`
5. Trainer 内部调用 Hugging Face `Trainer` 完成训练。
6. 训练结束后在测试集评估，并把结果写入 `outputs/<dataset>/<model>/...txt`。
7. checkpoint 保存到 `checkpoints/<dataset>/<model>/...`。

## 4. 入口文件 `main.py` 在做什么

`main.py` 是整个项目的统一入口，主要职责有 5 个：

1. 读取命令行参数，如数据集名、模型名、学习率、epoch、batch size。
2. 设置随机种子和运行设备（`cuda`、`mps`、`cpu`）。
3. 构造输出目录和 checkpoint 目录。
4. 根据任务类型实例化不同 Trainer。
5. 训练、评估、记录最佳 epoch 和测试结果。

它的设计思路是：

- 用一个统一脚本跑不同任务；
- 让“任务差异”下沉到 `src/tasks`；
- 让“数据差异”下沉到 `src/dataloader`。

这种结构适合后续扩展新数据集，因为只要补一个数据集类，并设置好 `problem_type`，主流程几乎不用改。

## 5. 三类任务 Trainer 的区别

### 5.1 `SequenceClassificationTrainer`

用于文本分类任务，包括：

- 单标签分类：如 `ChemProt`
- 多标签分类：如 `Phenotype`

主要做的事：

- 加载 `AutoTokenizer` 和 `AutoModelForSequenceClassification`
- 对文本做 tokenize
- 用 `DataCollatorWithPadding` 动态补齐
- 训练时按 `weighted_f1` 选最好模型

这里的关键点是：

- 多标签分类直接把 logits 用 `> 0` 做阈值切分；
- 单标签分类用 `argmax` 得类别；
- 指标在 `src/metrics/metrics.py` 里统一算。

### 5.2 `TokenClassificationTrainer`

用于序列标注 / 命名实体识别类任务，包括：

- `DEID`
- `COS`
- `SocialHistory`

主要做的事：

- 加载 `AutoModelForTokenClassification`
- 把原始 token 标签重新对齐到子词级别
- 对 `[CLS]`、`[SEP]` 和被拆分后的后续子词标记为 `-100`
- 用 `seqeval` 计算 `precision / recall / f1 / accuracy`

这是标准的 Hugging Face NER 训练套路。

### 5.3 `MaskClassificationTrainer`

这个类使用 `AutoModelForMaskedLM`，说明它不是普通分类，而是把任务改写成“掩码预测”。

它的特点：

- 训练阶段还是走 `Trainer`
- 测试阶段没有直接用 `Trainer.evaluate()`
- 而是调用 `evaluate_mmlu()`，逐条样本做 masked token 推理

不过在当前 `dataloader.py` 中，我看到实际实现的数据集主要是前两类和 token classification，仓库里这部分更像是为某类 prompt-style 任务预留的扩展接口。

## 6. 数据集层是整个项目最重要的部分

`src/dataloader/dataloader.py` 是最值得重点读的文件，因为这里决定了“原始临床/生物医学数据怎样变成模型可训练的数据”。

### 6.1 `Phenotype`

任务类型：多标签分类。

处理逻辑：

- 读取表型标注文件 `ACTdb102003.csv`
- 读取 `MIMIC III` 的 `NOTEEVENTS.csv`
- 用 `ROW_ID` 把标签和病历文本合并
- 过滤 `NONE=1` 但其他表型仍为 1 的冲突样本
- 生成 multi-hot 标签向量
- 划分训练/验证/测试集
- 缓存到 `data/processed/phenotype`

本质上，这是“给一段临床文本，预测它包含哪些 phenotype 标签”的任务。

### 6.2 `ChemProt`

任务类型：单标签分类。

处理逻辑：

- 分别读取 `train/dev/test.tsv`
- 把 `sentence` 重命名为 `text`
- 把 `label` 转成 `ClassLabel`
- 直接构造 `DatasetDict`

这个任务非常标准，代码也最简单。

### 6.3 `DEID`

任务类型：token classification。

这是一个去标识化任务，目标是识别病历中的敏感实体，比如：

- 姓名
- 日期
- 地点
- 年龄
- 电话

处理逻辑比较有代表性：

- 同时读取原文本 `id.text` 和脱敏结果 `id.res`
- 用正则提取 record
- 对比原文和带 mask 的版本
- 推断被替换片段在原文中的实际跨度
- 生成 BIO 标签

这说明项目作者不是直接拿现成 CoNLL 格式，而是自己从临床脱敏数据中“反推”实体边界。

### 6.4 `COS`

任务类型：token classification。

数据看起来是 `brat` 标注风格的 `.ann` 文件。处理逻辑是：

- 先从 `.ann` 中抽取 `Snippet`
- 再在 snippet 内部寻找 `Cos / Ref / Loc / Attr / Val` 这些 span
- 对文本进行分词
- 根据字符区间映射成 token 级 BIO 标签

适合做临床概念或观察片段的细粒度标注任务。

### 6.5 `SocialHistory`

任务类型：token classification。

也是读取 `.txt + .ann` 配对文件，然后：

- 解析标注区间；
- 将文本按非空白字符切分为 token；
- 根据字符偏移映射 BIO 标签。

标签体系更复杂，覆盖吸烟、饮酒、药物、职业、婚姻状况、居住情况等社会史信息。

## 7. 指标是怎么计算的

指标都集中在 `src/metrics/metrics.py`：

- 多标签分类：
  - `weighted_f1`
  - `micro_f1`
- 单标签分类：
  - `accuracy`
  - `weighted_f1`
  - `micro_f1`
- 序列标注：
  - `precision`
  - `recall`
  - `f1`
  - `accuracy`

这里有两个值得注意的细节：

1. 多标签分类没有显式 `sigmoid`，而是直接用 `logits > 0` 判正类。
   这是可行的，因为 `sigmoid(logit) > 0.5` 与 `logit > 0` 等价。
2. `main.py` 在选最佳 epoch 时固定查找 `eval_weighted_f1`。
   这对分类任务没问题，但对 token classification 来说最佳指标实际配置是 `f1`，所以“日志里记录的 best epoch”可能不总是准确反映 token 任务的最佳轮次。

## 8. continued pretraining 资源怎么理解

`pretraining_resources` 不是完整训练代码，而是“继续预训练时会用到的资源包”。

### 8.1 `convert_dataset_to_mds.py`

作用是把 CSV 文本数据转换为 `MDS` 格式，便于流式训练。

它适合大规模语料，特点包括：

- 支持大文件流式处理
- 可统计 token 数量
- 可选择 tokenizer
- 可拼接固定长度 token 序列

如果你想自己构建领域语料继续预训练，这个脚本很有用。

### 8.2 `configs/phase1` 和 `configs/phase2`

这两个目录对应 continued pretraining 的两个阶段：

- `phase1`：通用阶段，同时使用 biomedical + clinical 数据
- `phase2`：专门化阶段，只使用 clinical 数据

另外还有：

- `_phase2_bio_base.yaml`
- `_phase2_bio_large.yaml`

这两个看名字是 Bio ModernBERT 的专门化配置，但 README 明确说它们在测试中效果不如主方案。

## 9. 结果文件是怎么组织的

项目把实验结果拆成两部分：

### 9.1 `outputs/`

保存每次实验的文本日志，文件名里编码了超参数：

```text
lr=<lr>_wd=<wd>_epochs=<epochs>_seed=<seed>_effective_batch_size=<bs>.txt
```

日志里会记录：

- 测试集指标
- seed
- 有效 batch size
- best epoch
- 训练耗时
- 评估耗时

### 9.2 `checkpoints/`

保存模型 checkpoint。

Trainer 使用了：

- `save_strategy="epoch"`
- `load_best_model_at_end=True`（部分任务）
- `save_total_limit=1`

所以通常只会保留有限数量的 checkpoint。

### 9.3 `results/aggregate_results.py`

这个脚本会递归读取日志文件，把多 seed 的结果聚合成表格，并输出 `aggregated_results.csv`，适合做论文表格或实验汇总。

## 10. 怎么运行

### 10.1 环境安装

README 推荐：

```bash
conda env create -f environment.yaml
conda activate BioClinicalModernBERT
pip install "flash_attn==2.6.3" --no-build-isolation
```

其中 `Flash Attention` 是这个项目强调的关键依赖，因为 `ModernBERT` 很依赖它来发挥长上下文和效率优势。

### 10.2 单次实验

```bash
python main.py \
  --dataset Phenotype \
  --model thomas-sounack/BioClinical-ModernBERT-base \
  --lr 2e-5 \
  --wd 0.01 \
  --epochs 3 \
  --seed 42 \
  --batch_size 16 \
  --accumulation_steps 1
```

### 10.3 多 seed 并行实验

```bash
bash scripts/run_parallel.sh \
  --dataset Phenotype \
  --model thomas-sounack/BioClinical-ModernBERT-base \
  --lr 2e-5 \
  --wd 0.01 \
  --epochs 3 \
  --batch_size 16 \
  --accumulation_steps 1
```

脚本默认会并行跑多个 seed。

## 11. 需要注意的几个坑

### 11.1 原始数据不会自动下载

仓库只提供处理逻辑，不提供原始数据。你必须手动把数据放到 `data/raw/` 下面的对应目录里。

### 11.2 `run_parallel.sh` 的 conda 环境名和 README 不一致

README 里推荐激活的是：

```bash
conda activate BioClinicalModernBERT
```

但脚本里实际写的是：

```bash
conda activate bert24
```

如果你直接运行脚本，很可能需要先改成你自己的环境名。

### 11.3 这是研究代码，不是完整产品工程

你会看到很多实现都偏“实验复现导向”：

- 数据路径写得比较固定
- 部分任务接口预留了扩展，但当前仓库未完全展开
- 继续预训练只给资源和配置，不给完整训练框架

所以更适合：

- 复现论文实验
- 学习如何给生物医学任务接入 `ModernBERT`
- 在现有框架上增加自己的数据集

## 12. 如果你要继续扩展这个项目

最推荐的扩展路径是：

1. 在 `dataloader.py` 里新增一个数据集类。
2. 给这个类设置好：
   - `problem_type`
   - `dataset`
   - `num_labels`
   - `id2label / label2id`（如果是 token 分类）
3. 在 `get_data()` 中注册新数据集名字。
4. 复用现有 Trainer 直接训练。

也就是说，这个仓库的可扩展性主要建立在“数据集适配层”上，而不是主入口层。

## 13. 一句话总结

这个项目本质上是一个面向生物医学/临床 NLP 的 `ModernBERT` 实验框架：

- `main.py` 负责统一调度；
- `dataloader.py` 负责把不同医学数据集转成可训练格式；
- `tasks/` 负责适配不同任务头；
- `metrics.py` 负责统一评估；
- `pretraining_resources/` 负责提供继续预训练所需配置和语料转换工具。

如果你是做毕业设计，这个仓库最有价值的地方不是“直接跑起来”，而是它展示了如何把一个长上下文编码器系统化地接到多个临床 NLP 任务上。
